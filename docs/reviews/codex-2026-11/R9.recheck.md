## C. 新發現

### N1 [high] [code] [high] Player 的 crash log 可覆寫 `--db` 指定的資料庫

- **位置與證據**　`locations` 固定在 `--db` 的父目錄選 `crash.log`。若資料庫本身名為 `crash.log`，兩個路徑相同。Player 在載入 pack 前就設定日誌路徑，之後若載入失敗，`report` 會以 `std::fs::write` 截斷該檔案。[main.rs:50](D:/rust_learn/.claude/worktrees/r1/crates/axiom-player/src/main.rs:50) · [main.rs:140](D:/rust_learn/.claude/worktrees/r1/crates/axiom-player/src/main.rs:140) · [main.rs:173](D:/rust_learn/.claude/worktrees/r1/crates/axiom-player/src/main.rs:173)
- **影響與建議**　一次素材載入錯誤即可破壞既有 SQLite 資料庫。以 `create_new` 建立獨立日誌，遇到同名就換名，並測試啟動失敗後資料庫位元組仍完整。

### N2 [high] [human] [high] `--force` 會刪除含同名 JSON 的非成品資料夾

- **位置與證據**　`game_folder` 只檢查目錄中是否有名為 `game.json` 的一般檔案，空檔也會通過。發佈成功後會遞迴刪除整個備份。現有負面案例只用完全沒有 `game.json` 的目錄。[packaging.rs:346](D:/rust_learn/.claude/worktrees/r1/crates/axiom-runtime/src/packaging.rs:346) · [packaging.rs:441](D:/rust_learn/.claude/worktrees/r1/crates/axiom-runtime/src/packaging.rs:441) · [package-smoke-test.ps1:154](D:/rust_learn/.claude/worktrees/r1/scripts/package-smoke-test.ps1:154)
- **影響與建議**　誤選含同名檔案的工作目錄時，`--force` 會移除其內容。應先驗證有大小上限的 `GameManifest` 與對應的成品結構，再允許替換。補測含無效 `game.json` 的外部資料夾，並斷言其中檔案完整保留。

### N3 [medium] [collab] [high] 指紋符合審核值時，player 仍可使用另一個 pack 的存檔 ID

- **位置與證據**　`game.json.id` 取自複製前載入的來源 manifest。`pack_digest` 取自稍後複製的檔案。若磁碟上的 pack 在兩步之間從 B 換成已審核的 A，A 的指紋會通過，但 `game.json.id` 仍是 B。Staging 驗證只取 `.world`，player 則用 `game.json.id` 選資料庫。[packaging.rs:187](D:/rust_learn/.claude/worktrees/r1/crates/axiom-runtime/src/packaging.rs:187) · [packaging.rs:208](D:/rust_learn/.claude/worktrees/r1/crates/axiom-runtime/src/packaging.rs:208) · [packaging.rs:494](D:/rust_learn/.claude/worktrees/r1/crates/axiom-runtime/src/packaging.rs:494) · [packaging.rs:530](D:/rust_learn/.claude/worktrees/r1/crates/axiom-runtime/src/packaging.rs:530) · [main.rs:51](D:/rust_learn/.claude/worktrees/r1/crates/axiom-player/src/main.rs:51)
- **影響與建議**　人員收到指紋正確的成品，player 卻會開啟 B 的資料庫。應從已驗證的 staging manifest 產生遊戲 ID 與預設 title，或在兩次讀取不一致時拒絕發佈。
