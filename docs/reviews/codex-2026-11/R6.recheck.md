## C. 新發現

### N1 [medium] [collab] [high] Deadzone 拖曳可覆蓋 AI 剛提交的值

- **位置與證據**　Input Map 只保留草稿數值。若 AI 在拖曳期間提交新 deadzone，放開時 editor 會用當前 revision 當 `expected_rev`，將舊手勢的草稿寫回。**影響**　AI 的提交可被覆蓋，雙方都收不到 revision 衝突。**建議修正**　拖曳或輸入開始時記錄 revision，提交時沿用，並測試手勢中途有外部提交的情況。 [input_map.rs:568](/D:/rust_learn/.claude/worktrees/r1/crates/axiom-runtime/src/editor/input_map.rs:568) · [editor/mod.rs:2518](/D:/rust_learn/.claude/worktrees/r1/crates/axiom-runtime/src/editor/mod.rs:2518)

### N2 [medium] [human] [high] Input Map 將右側修飾鍵記成左側

- **位置與證據**　單獨按修飾鍵時，擷取程式只靠 `egui::Modifiers` 判斷變化，固定寫入 `ShiftLeft`、`ControlLeft` 或 `AltLeft`。遊戲端則讀實體 `KeyCode` 並精確比對。**影響**　例如按右 Shift 重綁後，editor 會成功保存左 Shift，剛按的右 Shift 無法觸發該 action。**建議修正**　讓擷取讀取與遊戲相同的實體鍵碼，並測試左右兩側。 [input_map.rs:152](/D:/rust_learn/.claude/worktrees/r1/crates/axiom-runtime/src/editor/input_map.rs:152) · [app.rs:3526](/D:/rust_learn/.claude/worktrees/r1/crates/axiom-runtime/src/app.rs:3526) · [world.rs:54](/D:/rust_learn/.claude/worktrees/r1/crates/axiom-runtime/src/world.rs:54)

### N3 [low] [collab] [high] 檔案音效的 `gain` 缺少 editor parity

- **位置與證據**　ACL 和 `ops::add_audio_file_clip` 都接受 `gain`，但 `audio.new_clip` 只有 preset、ID 和檔案欄位，送進共用 op 的 gain 固定為 `None`。現有 parity 測試只覆蓋預設增益。**影響**　人員無法透過同一個建立對話框重現 AI 以非預設 gain 建立的 clip。**建議修正**　加入 file gain 欄位，同步產生 ACL 預覽，並測試雙方提交相同的非預設值。 [acl.rs:1755](/D:/rust_learn/.claude/worktrees/r1/crates/axiom-core/src/acl.rs:1755) · [editor/options.rs:202](/D:/rust_learn/.claude/worktrees/r1/crates/axiom-runtime/src/editor/options.rs:202) · [editor/mod.rs:1502](/D:/rust_learn/.claude/worktrees/r1/crates/axiom-runtime/src/editor/mod.rs:1502) · [parity.rs:483](/D:/rust_learn/.claude/worktrees/r1/crates/axiom-runtime/src/editor/parity.rs:483)
